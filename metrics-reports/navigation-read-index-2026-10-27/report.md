# 搜索与分类只读快照索引优化

2026-10-27，Apple M5，darwin/arm64，Go 1.27.3，基准默认 GOMAXPROCS=10。
基线为 `e9cadb6245cc8bc28bf5cda06a55cf5af79dd00f`；候选实现摘要见
[source-manifest.json](source-manifest.json)。本报告只描述渲染旁路，不代表全站延迟或 RSS。

## 改动与安全边界

页面搜索和分类路径不再先 `NavigationView.Copy()` 克隆全部条目。渲染器从已授权、
固定版本的 view 取得条目值；分类元数据仍提供调用方副本，匹配索引也归请求所有。
页面搜索复用建议接口使用的归一化快照字段；有搜索时才初始化这些字段。
分类索引按快照惰性建立，选中分类直接输出，避免为其他分类建立临时分组。
未指定分类的现有分组行为保留，不新增分类 HTML 缓存或任意查询缓存。

公开视图仍先过滤私有条目及私有父分类，再匹配和选择。动态 URL 在请求内展开。
加载 view 之前的文件检查、应用/书签配对选择、配置读取和最终持久化会话检查均保留。
没有修改 `internal/auth`、`internal/security` 或原始配置读取协议。

## 基准范围

同一基准文件分别与冻结基线源码、候选源码编译。使用 Go overlay 恢复五个生产文件，
基线禁用依赖新增 API 的两个测试文件；基准本身两版相同。不重置当前工作区。
初始改动前也测量过基线；报告使用最后串行复测的原始结果，排除与全量回归同时运行
的中间测量。基线先运行、候选后运行，每场景三轮各 500ms，指标取三轮中位数。
未轮转两版执行顺序，未计算置信区间，几个百分点差异不作为稳定加速保证。

测量前已选择并预热匿名授权 view 和索引，计时只覆盖 `navigationFragment` 旁路的
搜索/分类及 HTML 生成，并逐次检查与预热结果一致。不包含文件加载、HTTP、认证事务、
网络、冷索引构建、浏览器 DOM、并发饱和或服务端日志。不能从 ns/op 推导完整请求 p95。

每集合 1,000 或 10,000 条公开条目；普通夹具还有私有哨兵。
`apps-hit` / `bookmarks-hit` 查询 `public-99`，分别命中 11 / 111 条；
`*-miss` 查询不存在的文本。`category` 选中的分类包含全部公开条目；
`category-sparse` 使用 20 个均匀分类，选一个分类，输出 50 / 500 条。
所有分类场景使用 tabs 布局。各场景独立预热，均为静态 URL。

- `1000/apps-hit`：51.93 → 18.62 µs/op（减少 64.1%）；120,429 → 13,879 B/op（减少 88.5%）。
- `1000/bookmarks-miss`：43.22 → 7.82 µs/op（减少 81.9%）；115,773 → 9,221 B/op（减少 92.0%）。
- `1000/bookmarks-hit`：51.40 → 17.13 µs/op（减少 66.7%）；119,208 → 12,655 B/op（减少 89.4%）。
- `1000/category`：196.92 → 189.41 µs/op（减少 3.8%）；431,165 → 316,430 B/op（减少 26.6%）。
- `1000/category-sparse`：38.49 → 12.85 µs/op（减少 66.6%）；141,539 → 20,307 B/op（减少 85.7%）。
- `10000/apps-miss`：423.04 → 89.19 µs/op（减少 78.9%）；1,122,463 → 81,932 B/op（减少 92.7%）。
- `10000/apps-hit`：514.69 → 185.73 µs/op（减少 63.9%）；1,179,426 → 138,885 B/op（减少 88.2%）。
- `10000/bookmarks-miss`：421.96 → 80.91 µs/op（减少 80.8%）；1,123,487 → 82,957 B/op（减少 92.6%）。
- `10000/bookmarks-hit`：483.30 → 161.44 µs/op（减少 66.6%）；1,158,265 → 117,722 B/op（减少 89.8%）。
- `10000/category`：1900.93 → 1804.73 µs/op（减少 5.1%）；4,275,147 → 3,152,723 B/op（减少 26.3%）。

搜索与稀疏分类的渲染旁路有明确的耗时和分配改善。全量分类输出仍主要承担 HTML
生成，耗时仅小幅下降；不将约 4%–5% 的差异当作确定的端到端改善。
匹配数组仍为请求分配，HTML 转义、URL 策略和结果正文生成也仍有成本。

## 内存代价与限制

归一化搜索字段和分类条目索引保留在不可变内容快照上，空间随条目及字符串长度增长。
分类索引只在分类访问时初始化；默认无搜索页面不会因此初始化搜索字段。
公开和管理员视图分别保留索引，旧 view 被在途请求持有时也会保留旧索引。
本轮没有测量稳态堆、RSS 或冷启动，分配减少不等于常驻内存下降。

## 复现

从仓库根目录运行，需要 Go 1.27.3、Python 3 和基线 Git 对象；浅克隆需要先取回该提交。
脚本创建临时 overlay，按基线、当前源码顺序测量，要求输出目录尚不存在：

```sh
python3 metrics-reports/navigation-read-index-2026-10-27/compare.py /tmp/flare-read-index-replay
```

只测当前源码：

```sh
go test ./internal/pages/home -run '^$' -bench '^BenchmarkNavigationReadIndex$' -benchmem -benchtime=500ms -count=3
```

复测前停止其他构建、测试和 profile；新结果保存到新目录，不覆盖本次记录。
