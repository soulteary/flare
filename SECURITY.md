# Security policy

## Versions and updates

When reporting a security issue, include the exact version or source commit and,
for containers, the image digest. Check the [latest stable release](https://github.com/soulteary/flare/releases/latest)
for available fixes. Development changes on `main` are not available in a stable
image until that release is published. Do not assume older releases receive
backported fixes; consult the release notes for the version containing a fix.

## Reporting a vulnerability

Use **Report a vulnerability** on the repository's
[Security page](https://github.com/soulteary/flare/security) when that option is
available. If no private reporting option is offered, open a minimal issue asking
a maintainer for a private contact method. Do not include exploit instructions,
credentials, private bookmark data or affected public deployment addresses in
that public request. Share reproduction details through the private channel once
it has been established.

A useful private report includes the affected version, deployment conditions,
expected and actual behavior, impact, and a minimal reproduction with synthetic
data. Remove passwords, cookie signing keys and session cookies from attachments.
Ordinary bugs without security-sensitive details can use public issues.
