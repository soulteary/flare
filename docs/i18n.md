# Internationalization

Flare's web interface supports Simplified Chinese (`zh`, the default) and
English (`en`). Choose the language in Settings → Appearance. The choice applies
to the site, including the editor and bookmark transfer screen. Browser headers
and query parameters do not override it.

Regional aliases such as `zh-CN`, `zh-Hans`, `en-US` and `en_GB` are normalized to
`zh` or `en`. Chinese aliases, including `zh-Hant`, currently select the Simplified
Chinese catalog; this is not a separate Traditional Chinese translation.
Unsupported values in existing configuration files fall back to English. The
settings form rejects unsupported languages, and older forms that omit the
language retain the existing choice.

## Translation architecture

`internal/i18n` wraps `github.com/soulteary/i18n-kit/v4` with an application-owned
bundle. The JSON catalogs in `internal/i18n/locales` are embedded and loaded at
startup. A missing or invalid catalog stops startup with an explicit error.
Requests pass their language explicitly; they never mutate the library's global
language. Missing translations fall back to English, then the message key.

Keep existing `T(locale, key)` and `Tf(locale, key, args...)` calls for simple and
printf messages. Use `Format(locale, key, params)` for complete sentences with
named parameters. A missing `Tf` key returns the key without exposing arguments.
Use `HTMLLang` for document language tags.

Templates translate text through `{{ T .Locale "message.key" }}`. Go's HTML
formatter escapes translated text in its output context. Do not cast dynamic
translations to `template.HTML`. User-defined names, URLs, descriptions, titles,
footers and greetings are content, not translation keys.

The editor serializes translated messages through an escaped data attribute.
JavaScript calls `t('editor.message', {name: value})` and writes user text through
DOM text APIs. Named parameters are substituted once; parameter values containing
braces are not interpreted again. Static labels are rendered by Go templates,
without scanning or replacing user text in the DOM.

## Adding or changing messages

1. Add the same semantic key to both JSON catalogs. Translate a complete sentence
   instead of concatenating separately translated fragments.
2. Keep parameter names and printf arguments consistent across languages.
3. For editor client messages, expose the key through `editorMessages` or
   `editorCompositeMessages` in `internal/pages/editor/i18n.go`.
4. Edit source templates under `embed/templates`, then run `go run ./build` to
   regenerate the embedded release templates. Debug mode reads source templates;
   release mode reads generated templates under `internal/resources/templates/html`.
5. Run `go test ./...` and the editor's Node/browser checks when changing client
   behavior. The i18n tests check catalog and parameter parity and concurrent
   language isolation.

Adding another language also requires extending the application's language
allowlist, settings choices, HTML language tags and date formatting. The upstream
library recognizing a language does not mean Flare has translated that language.

This change localizes the web navigation, settings shell, editor, authentication
errors and transfer interface. CLI help, operational logs, documentation, upstream
weather content and low-level diagnostic strings retain their original language.
