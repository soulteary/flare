# 登录与私有访问：开发分支升级指南

本文针对当前 main 的阶段一开发实现，不属于稳定版 0.6.7。新安装及账号操作见[账号指南](accounts.md)，完整参数见[配置参考](configuration.md)，备份恢复见[恢复指南](backup-restore.md)。三个 YAML 文件继续是内容与设置来源；没有内容数据库迁移，不需要为书签增加 ID、版本或成员字段。

## 更新前

1. 记录旧镜像标签和摘要，或保留原二进制。保留 Compose、应用工作目录 `.env`、启动参数和 Secret。
2. 停止实例，复制整个工作目录，包括 `apps.yml`、`bookmarks.yml`、`config.yml`、`.flare-cookie-secret`、已有导入备份和隐藏文件。只导出书签不是完整备份。
3. 确保工作目录可创建持久的 `.flare-security/`。已有整目录挂载一般无需新增挂载；只挂载三个 YAML 文件时，另挂载这个目录。例如原文件挂载保持不变，再增加 `./security:/app/.flare-security`。可选 `FLARE_STATE_DIR` 改路径。
4. 可在停止旧服务后运行新二进制 `flare security migration-check --json`。这是只读检查，不替代完整备份，不输出密码和私人 URL。

应用不能可靠识别 Docker 的全部挂载方式，启动成功不等于状态已持久化。不要通过 privileged 解决目录权限问题，也不要用删除安全目录当作密码恢复。

## 正常升级

保留原 YAML/参数，更新镜像并重建容器（环境/镜像变化不能只 restart），或换用新二进制按原参数启动。有效旧登录部署自动迁移，原用户名/密码/访问模式保持；旧 Cookie 会失效一次，重新登录即可。旧短密码只提示，不因强度门槛丢失访问。

显式旧部署凭据默认继续由 Compose/.env/环境管理：有效账号密码变化后重建会撤销旧会话。同值重启不会反复改密。希望在网页修改密码，可在账号页验证原密码并明确转为应用管理；之后遗留 FLARE_PASS 不会覆盖新密码。反向切换用停机 `flare security set-credentials --mode deployment`，密码来自有效部署源。

识别到旧免登录且没有私有标记时，原匿名内容管理方式保留，启动报告说明这是网络信任模式；若来自旧默认也会标明意图未知，不宣称安全。纯默认样例与新样例不能可靠区分时不会自动公开；确认确为旧默认部署可停机运行 `flare security adopt-legacy-defaults`。

新实例默认需建立管理员且全站私有。可使用 `flare security init --username NAME` 隐藏输入新密码，或通过有效启动密码输入建立。维护命令的密码可用 `--password-file PATH` 读取，不提供明文密码命令行参数。

## 升级后检查

- 确认启动状态 ready，无需改写 YAML。已有 private=true 在登录部署中现在真正生效；公开站点中这些条目会对匿名隐藏。
- 独立无 Cookie 窗口检查导航、搜索、旧跳转、编辑器和导出。不要用管理员能看到内容来推断匿名保护。
- 在账号页确认密码来源及退出当前/全部行为；普通重启不应清空未过期会话。
- 重建容器，再次确认账号、实例身份和会话策略保持，证明安全目录确实持久化。
- 通过以上检查后再开放公网。完整子路径、多副本和网络盘并发写不属于本阶段支持范围。

## 需要处理的少数情况

免登录与任意分类/条目 private=true 同时存在时，全业务暂停。选择在原配置启用登录并提供密码，或停机逐项检查并去掉不需要的私有标记，再重启。程序不会替用户清除 private。

PRIVATE 与免登录并存、Visibility/布尔值非法或同时提供密码明文和文件时，修正报告指出的源配置；不回落公开。优先级仍是 CLI > 工作目录 .env > 进程环境 > 默认。

旧密码只存在历史日志且没有有效持久源时，程序不能找回。停机提供 FLARE_PASS/FLARE_PASS_FILE，或 `flare security reset-password` 建立应用管理密码；原站点访问方式不被关闭。部署管理模式恢复优先改源，明确接管才用 `--take-local-control`。

已完成迁移后状态文件/标记缺失、损坏或不可写，应修权限或恢复整套安全目录，不重新初始化。只读 YAML 可浏览；编辑/导入会明确失败，不通过另存副本绕过原文件写入失败。

已有 YAML 锚点、别名和合并键（`&name`、`*name`、`<<`）继续按有效值读取，分类和条目通过别名继承的 `private: true` 同样受保护；循环、过量展开或非布尔私有值拒绝加载。为避免网页重写改变共享节点含义，含锚点/别名的文件暂为网页只读：原始 YAML 导出保持字节，编辑或导入覆盖明确返回只读错误。继续手工改原文件并重启，或备份后自行展开为普通映射再使用网页编辑；程序不会自动展开、重写这些老配置。

首次迁移快照在 `.flare-security/migration-backups/`；它记录原 YAML、旧安全材料、摘要和迁移过程，不能代替外部 Compose/Secret 完整备份。中断重试保留首次快照，修正后的输入另存快照，不覆盖首次备份。

## 回滚到旧版

1. 停新版并隔离公网，另存新版全部数据和安全目录，保留升级后的新增/修改内容。
2. 恢复升级前整个工作目录、部署配置、Secret 和挂载，换回记录的旧镜像/二进制；不要只降镜像继续混用新安全状态。
3. 隔离启动旧版，检查实际匿名导航与管理权限。
4. 特别注意：旧版可解析 YAML，不代表它执行 private 保护。若需保持新私有内容保密，旧版必须同时设 `FLARE_DISABLE_LOGIN=false`、`FLARE_VISIBILITY=PRIVATE` 并验证有效，或先移除这些内容，再放行公网。
5. 新增内容留在独立备份，人工确认后合入；不能自动把含私有数据的导出合到旧公开站点。

恢复旧 Cookie 密钥可能让旧 Cookie 重新有效；安全事件回滚应按旧版支持方式轮换密钥。新版网页改密不会反写旧部署密码，回滚后使用旧配置的密码，注意重新采用旧泄漏密码的风险。

## 恢复到新版

停止服务，恢复一致性完整目录和外部源，保留恢复前副本；启动前执行 `flare security revoke-all`，成功后再启动并检查账号、资源权限和匿名入口。普通目录复制可能包含历史会话，不能省略撤销。只替换某个 YAML 是内容恢复，不等于完整实例恢复。

## 可选部署输入

- `FLARE_PASS_FILE`：只读密码文件，最多 514 字节输入，只移除一次末尾 LF/CRLF；其他空白保留。有效源不能与非空 FLARE_PASS 并用。
- `FLARE_CREDENTIAL_MODE=local|deployment`：新初始化或明确来源切换的高级选项；已存模式矛盾时要求显式切换，不静默重置。
- `FLARE_EXTERNAL_URL`：规范 HTTP(S) origin；`FLARE_ALLOWED_HOSTS` 逗号分隔主机/端口；`FLARE_TRUSTED_PROXIES` 逗号分隔 IP/CIDR。普通保留 Host 反代无需全填；只有受信代理头影响来源，HTTPS Cookie 不因故障自动降级。
- `config.yml` 的可选 `LoginFooter`：文本或经过安全过滤的 HTTP(S) 链接 HTML，默认空；不继承原 Footer，不允许脚本/图片/iframe。原 Footer 仍在原已授权导航使用。

详细交付与验收边界见[需求](requirements/login-private-access.md)和[阶段一规格](requirements/login-private-access-phase1.md)。
