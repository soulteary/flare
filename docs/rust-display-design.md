# Go 管理端与 Rust 展示端拆分方案

状态：待评审的架构提案，尚未实现。基于 2026-10-27 的主分支
`e9cadb6`。本提案不承诺 Rust 的性能收益，也不改变已发布版本的行为。

## 目标与首期范围

保留 Go 的管理、配置、持久化和认证积累，将稳定、高频的展示计算逐步迁入
Rust。首期只验证应用页和书签页渲染；Go 仍是公开 HTTP 入口及安全决策者，
Rust 是内部渲染进程。CSS、浏览器脚本、图标资源和页面语义尽量复用。

是否扩大迁移，应取决于同等安全语义下的延迟、CPU、总内存、部署及维护成本。
双进程通信和现有 HTML 缓存可能抵消渲染收益，不能以语言替换代替测量。

## 当前代码提供的边界

- [路由装配](../internal/server/router.go)统一安装认证、页面及资源路由；安全启动
  未就绪时只返回不可用页面。
- [首页处理](../internal/pages/home/home.go)同时承担配置选择、身份判断、展示变量
  组装、搜索和渲染，不能作为一个纯展示包整体搬迁。
- [请求设置快照](../internal/pages/home/read_mode.go)在单次请求中复用结果和错误。
- [可见性与导航读取](../config/data/visibility.go)在计数、匹配和渲染前过滤私有
  分类及条目，并在同一读锁内选择应用和书签。私有父分类不能被公开子条目覆盖。
- [配置更新](../config/data/settings.go)和[编辑器提交](../config/data/editor_document.go)
  使用不同的协调机制，现有导航成对读取不等于设置与导航的全局事务。
- [持久化认证](../internal/auth/persistent.go)在部分缓冲页面发送前再次检查会话、
  过期及存储状态；[SessionProof](../internal/security/store.go)绑定单次请求及 Store。
- [导航缓存](navigation-cache.md)已经缓存默认导航 HTML，仍保留数据及最终认证检查。
  当前内容编辑并不承诺取消所有已经开始的页面响应。

## 职责归属

### 保留 Go

- `/settings`、`/settings/*`、`/editor`，导入导出、备份恢复及 `/guide`。
- `config/data` 的原始文件读写、默认值、校验、兼容迁移、版本冲突及恢复。
- `internal/auth`、`internal/security`：登录、退出、全部撤销、改密、重新认证、
  限速、CSRF、请求级会话检查及最终放行。
- Host、Origin、外部地址、可信代理和写入来源策略。
- 天气采集、地点迁移、后台刷新与失败重试。
- 初期保留首页 `POST /`、`POST /search/suggest` 的 HTTP 处理，以及 `/redir/url`。
- CLI、安全启动、日志、健康检查和运维工具。

### 适合迁入 Rust

1. `/applications`、`/bookmarks` 的 HTML 生成、分类布局、空状态及过滤展示。
2. `/`、`/help` 的展示组合；Go 继续提供规范化输入及必要的请求级字段。
3. 已过滤导航数据的本地搜索、排序及建议计算。
4. 静态资源服务，保留 HEAD、Range、条件请求、内容类型和错误缓存行为。

搜索目标解析、外部跳转、动态 URL 与完整建议接口放在后续阶段。Rust 不直接
读取或修复 YAML，不读取安全目录，不生成或验证管理端凭据。

## 首期部署与请求路径

同一个发布包或容器包含两个进程，通过 Unix socket 通信；需要其他平台时再
设计等价的受限本机传输。通信端点使用文件权限隔离，Rust 不公开内部接口。
由部署入口统一监督两个进程，保证退出、超时和重启行为可观测。

```text
浏览器 → Go HTTP 入口
           ├─ 管理、账户、写入、跳转 → Go
           └─ 展示请求
                → Go 检查身份、数据状态并选择快照
                → Rust 按指定版本生成完整缓冲响应
                → Go 最终检查并放行
```

建议内部协议先使用有大小限制的 JSON 消息，不首发引入 FFI 或共享可变内存。
快照按版本发布一次，页面请求仅传快照引用与请求参数，避免每次复制整个数据集。

渲染请求包含页面枚举、快照 ID、Go 决定的 audience、搜索词、分类及经过来源
策略处理的请求上下文。浏览器传入的身份头和权限参数不能决定 audience。
Rust 的返回值只允许受限状态、正文及明确列出的展示元数据；Cookie、缓存策略、
重定向及安全头由 Go 控制，不能透传任意内部响应头。

Rust 超时、崩溃、返回未知快照或非法协议时拒绝该次响应。恢复 Go 渲染应通过
明确的部署开关实施，并经过相同权限和数据检查，不能自动退回未经验证的旧 HTML。

## 展示快照契约

建立独立 DTO，避免直接序列化 `model.Application` 或 Go 内部缓存结构。

```text
DisplaySnapshot
  schema_version          协议版本
  instance_id             实例身份
  content_revision        完整展示内容版本
  policy_revision         展示授权与服务策略版本
  audience                public / administrator
  presentation            标题、语言、主题、布局、时钟及显示选项
  applications            有序应用集合
  bookmark_categories     已过滤分类
  bookmarks               有序书签集合
  search_options          Go 校验及规范化后的搜索选项
  asset_manifest_version  配套资源与模板版本
```

协议应明确字段类型、缺省值、枚举、字符串及集合大小限制、URL 策略和版本兼容规则。
未知的安全相关版本必须拒绝，不可忽略。内容版本不得在重启后误指向不同数据。

Go 分别生成 public 和 administrator 视图。公开快照不包含私有条目、分类、
计数或索引；Rust 只在已经授权的数据上搜索。完整快照只存在于受信任内部进程，
不提供浏览器可下载的快照接口。两种视图必须使用分离的缓存键。

`DisableLoginMode` 在当前实现中使 `CheckUserIsLogin` 返回真，不能把无 Cookie
自动等同于 public；模式解释继续由 Go 负责。

Cookie、身份、CSRF、当前 Host、协议、查询和分类不进入共享内容快照。
请求级展示数据单独传递，不允许写入跨请求 HTML 缓存。

普通名称和描述按文本转义。当前 `template.HTML` 页脚和内置 SVG 需要分别定义
明确的富文本及可信资源契约，不能让 Rust 对任意字符串关闭转义。CSP 与时钟、
搜索脚本的资源版本一起校验，避免旧策略配新脚本。

天气使用独立快照，包含地点身份、更新时间及有效期。Go 调度后台刷新，不能依赖
已被迁走的首页处理器触发采集。更换地点立即停止展示上一地点结果；同地点上游
失败可按当前策略使用旧结果。天气不触发整份导航索引重建。

## 一致性、发布与失效

增加 Go 展示发布协调器，覆盖设置、应用、书签和展示策略的版本选择。
不能只复用导航读锁后宣称全局一致；实现时需统一锁顺序，或用版本复核重试
形成完整候选版本，避免死锁及混搭。

发布流程：持久化提交成功 → 构造完整候选快照 → Rust 校验并装载 → 确认可渲染
→ Go 激活。请求固定使用一个版本。Rust 重启后重新装载当前版本，装载完成前
不接收展示任务。旧版本采用有界保留与回收，快照、索引及 HTML 缓存均限制内存。

必须区分“配置已持久化”和“展示已激活”；持久化成功但装载失败不能假报全部
生效，也不能盲目回滚磁盘数据。管理端应能够明确呈现发布失败和重试状态。

- 普通样式更新失败可按显式策略继续旧版。
- 公开改私有、删除内容、整站转私有等收紧可见性的提交，先使旧策略版本停止
  被放行；新版本未就绪时返回不可用。发送前检查策略版本。
- 上述内容策略门是本提案新增的保证，不应描述成当前已实现的内容撤销语义。
- 原始配置被删除或不可读时，继续保留当前读取失败语义，不能由快照隐藏故障。
- 支持直接编辑 YAML 时，由 Go 观察并复核文件变化；不能只监听管理接口提交。
  文件监听只能用作提示，读取检查及版本复核仍是判断依据。
- 对会话撤销与内容收紧分别定义最终检查的授权时点；已经发出的响应无法召回，
  不承诺撤销能取消客户端已收到的内容。

## 认证与最终放行

Go 获取请求身份并选择视图；Rust 返回完整、有界的缓冲正文；Go 在写入网络前
执行适用的最终会话及策略检查。检查失败时丢弃正文与相关元数据。受保护 HTML
禁止提前发送响应头、流式正文或用私有 ETag 提前生成 304。

保留当前 GET、HEAD、搜索建议和前台活动的会话续期差异，不能让资源请求或内部
渲染请求延长会话。保留 `private, no-store`，CSRF、近期重新认证及写入前的
授权检查始终在 Go。Unix socket 权限及受信任调用方负责内部请求身份，不向
Rust 传原始会话 Cookie 或共享签名密钥。

`SessionProof` 不能序列化为跨进程通行证。首期不引入 Rust 本地验证的长期 JWT，
避免重写退出、改密、全部撤销、持久化失败及时间回退处理。

## 跳转及资源兼容

[不透明句柄](../config/data/navigation_handle.go)由 Go 的当前内容快照生成。
Rust 使用 Go 提供的跳转引用；句柄与展示版本必须协调，旧句柄不能重新指向另一个
目标。[跳转处理](../internal/misc/redir/redir.go)继续检查当前可见性、目标合法性及
请求来源。编码链接不是加密或授权。

动态 URL 按请求展开，不能将一个客户端 Host 的展开结果共享给其他客户端。
生成跳转链接需保留 `from` 等来源语义及扩展链接兼容行为。

静态资源只通过明确路由清单公开；不能因为路径以 `/assets/` 开头就放松认证或
缓存策略。资源不存在及非法 Range 等失败不能继承成功资源的 ETag 或长期缓存。
具备内容哈希且保证不变的资源才适合长期缓存，其余沿用重验证策略。

## 后续 Rust 直接入口的条件

先允许明确公开的静态资源直达 Rust。匿名 HTML 是否绕过 Go，作为独立设计决定：
必须解决策略收紧同步、带 Cookie 请求分流、安全初始化失败、进程断联及旧快照
失效。仅依赖异步通知或短期令牌会引入陈旧授权窗口。

Go 故障时继续展示旧公开内容会改变当前失败时停止展示的策略。若要求保持当前
语义，则保留 Go 页面入口；不以心跳租约宣称实现立即撤销。

## 迁移步骤与验收

1. Go 内提取 DTO、发布协调及契约测试，现有 Go renderer 使用同一展示输入。
2. Rust 实现应用页和书签页，在测试或显式影子模式下比较输出，不向访客同时
   发送两个版本。使用合成数据，避免调试输出记录私人 URL。
3. 迁移首页、帮助页及静态资源，验证布局、脚本、语言和 CSP。
4. 迁移本地搜索计算，保持 HTTP 层认证、限速、来源及跳转策略。
5. 对照测量后决定继续、停在当前边界或恢复 Go 渲染。

验收覆盖私有父分类、私有条目、搜索建议、计数、无登录模式、动态 URL、句柄
过期、非法链接、模板转义、CSRF 和缓存隔离；覆盖渲染期间退出、改密、全部撤销、
存储异常、取消和超时；覆盖文件缺失、并发发布、进程重启、协议不兼容及旧版本回收。

复用现有导航 DOM fixtures、浏览器测试、认证与资源测试作为行为依据，新增
跨语言契约及故障注入测试，而不是重新实现一套与原行为无关的预期。

基准比较当前 Go 缓存热路径与双进程完整请求路径，保持数据规模、身份模式、
安全检查、压缩和并发一致。分别记录冷启动、冷/热缓存、p50/p95/p99、吞吐、CPU、
两个进程合计 RSS、暂态分配、包体积及构建发布成本；私有会话及策略变更路径也要
纳入测量。迁移前约定项目可接受的收益门槛，未达到时不扩大范围。
