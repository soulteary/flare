# 管理员资源开销归因与热点优化验收

## 测量前冻结的实验设计

2026-10-27，Apple M5 / 10 CPU / 32 GiB / macOS arm64。固定输入为既有 20,000 条、100 分类、10,000 私有条目，夹具摘要 `9537f2d51a70b2944ccbe6945eabdef698d6900326e2ee4d0c444d14c310214b`。此前饱和负载下 CPU/RSS 与吞吐同时上升，不能仅凭相关性判定为吞吐增加所致；本轮使用等输入速率和采样归因。

正式固定开放式到达率：管理员读取 **3 请求/秒**，首页/搜索严格交替，每轮实际 **180 秒**、计划 540 次读取；最多 4 个在途，等待队列容量 0，忙或调度落后记录丢弃，不无限补发。独立登录→私有读取→当前退出→旧 Cookie 重放探针 **每两秒**计划一次，最多 1 个在途、队列容量 0，共计划 90 次。两版完成读取数、探针数、丢弃及异常必须匹配，才据此归因资源变化。

沿用事前绝对预算：首页 p95 < 3 秒、搜索 p95 < 1 秒、RSS < 1 GiB。成功读取必须 HTTP 200 且包含实际授权卡片；退出后重放 HTTP 200 且不含私有卡片。等速率实验与后续饱和实验分别报告，不混为同一吞吐。

不可变原生基线：`b0ffcb369d3f5f149baa46ced5d4ee37c9a1476a89c4ed7b4a61e02d12b072cf` 和 `4396a134ca328ea60f7ac1ad3bc79701fea366c6aa2c6311096a4fa2e2140d45`。原生二进制仅能从 OS 读取 CPU 累计秒数及 RSS，不能从 RSS 推导分配字节或存活堆。测试专用 wrapper 在单独的 `127.0.0.1` 控制端口提供 runtime/pprof；生产二进制没有新增 profiling 路由。每轮记录实际摘要与 source provenance。

主要归一化指标：进程 CPU 秒 / 完成读取数、runtime TotalAlloc 增量 / 完成读取数、malloc/free/GC/暂停增量、HeapAlloc/HeapInuse、计时外强制 GC 后保留堆及 RSS。分母虽为读取数，分子包含相同数量的登录撤销探针，明确为固定混合负载成本，不能称作单个纯读取的精确成本。OS `ps time` 记录累计 CPU，保留其采样精度；`ps %cpu` 只作辅助观察。

pprof 预热后保存分配起点，使用 end−start 差分剔除启动 YAML 解析。runtime 累积分配计数为主要定量依据，pprof 默认采样估计用于解释热点。强制 GC 在计时与 CPU profile 之外，前后 profiling wrapper 使用相同采样与控制操作。短诊断定位热点，不替代正式每轮 180 秒。正式测量只在所有 agent 确认空闲后顺序执行。

最初预声明 6 请求/秒经容量校准发现原始构建 1,080 次计划只接纳 1,055 次（25 次在途上限丢弃）；它未达到严格等完成量条件，不用于等吞吐因果结论。其对应的优化版 6 请求/秒临时轮次已中止、保存部分记录并清理进程。**在任何 3 请求/秒结果产生前**将全部正式等速率轮次共同冻结为 3 请求/秒（540 次），探针仍 90 次、并发/队列/时长和绝对预算不变。若正式 540 次仍无法全部接纳，则如实报告而不继续事后降低。30 秒 6 请求/秒 profile 仅用于定位热点。

## 完成结果

正式轮次均于 2026-10-27 在上述同一台空闲开发机顺序完成。最终原生构建 SHA-256 为 `ecb66530e0252f551b2bd5a7f6bd68ff49bdb96cc04c5d26d365fa3f57efbc42`，最终 profiling wrapper 为 `f7a3ff2c9fff31b86a025f24f6fc5572199beb7cf9908ffde80ec8a3ddd8c914`。全部正式等速率轮次完成 **540 次读取、90 次安全探针，零丢弃、零请求异常、零私有内容断言失败**。每轮首页累计响应 729,236,520 字节、搜索 10,188,450 字节，输出工作量一致。机器判定见 [verdict.json](../../metrics-reports/admin-resource-analysis-2026-10-27/verdict.json)，全部冻结门槛通过。

原生等速率结果解释了此前饱和测试中 CPU 与 RSS 同时上升的疑问：在相同完成量下，原始 b0 构建 CPU 为 23.74 秒，请求内鉴权证据优化版 4396 为 21.96 秒，下降 **7.50%**；峰值 RSS 为 140.72→141.20 MiB，增加 0.48 MiB。此前饱和吞吐约翻倍时的资源上涨，不能直接解释成每次请求更贵。这是一组同机观测，不是跨设备或统计显著性结论。

本轮热点优化的主要收益是减少 CPU 和分配，吞吐提升较小：

- **原生固定 3 请求/秒：**4396→最终版，CPU 21.96→14.71 秒，即每完成读取的固定混合负载成本 40.67→27.24 毫秒，下降 **33.01%**；峰值 RSS 141.20→134.28 MiB，下降 **4.90%**。
- **相同 wrapper 的固定速率：**CPU/读取 40.26→28.98 毫秒，下降 **28.03%**；累积分配 18,805,410,624→7,793,687,792 字节，每读取 34,824,834→14,432,755 字节，下降 **58.56%**；GC 844→259 次，下降 **69.31%**；累计 GC 暂停 280.55→38.03 毫秒。wrapper 的 CPU 只与相同 wrapper 比较，不能与原生 CPU 混用。
- **重新配对的四并发饱和读取：**两版各实际 180 秒，4396 完成 3,401 次、最终版 3,537 次，吞吐 18.88→19.64 次/秒，增加 **3.99%**；峰值 RSS 217.47→168.83 MiB，下降 **22.37%**。两版均完成 64 次安全探针，所有读取 HTTP 200、登录 HTTP 303，无私有内容失败。最终首页 p95 290.45 毫秒、搜索 p95 246.37 毫秒。

以上原生/采样轮次均满足首页 p95 <3 秒、搜索 p95 <1 秒、RSS <1 GiB 的事前预算。RSS 使用内核子进程高水位，另保留每两秒采样；CPU 使用进程累计 CPU 时间差。原生 `ps time` 在本机有 10 毫秒精度，未把瞬时 `%cpu` 当作累计开销。

UTC 计时区间：原始原生 02:28:19–02:31:19，请求证据版原生 02:32:10–02:35:10，优化前 profile 02:35:37–02:38:37，最终 profile 02:56:08–02:59:08，最终原生 02:59:53–03:02:53，饱和优化前 03:03:50–03:06:50、最终版 03:07:14–03:10:14；北京时间均加八小时。每轮保留实际单调时钟时长及二进制摘要。

## pprof 归因与实现

分配差分剔除了启动 YAML 解析。优化前采样累计分配中，`strings.Builder.WriteString` 约 6,553 MiB，`slices.Clone` 约 2,684 MiB，书签分组渲染累计约 8,989 MiB。主要浪费来自重复克隆、完整书签结构按分类重复整理，以及分组字符串增长和复制。优化后 `slices.Clone` 约 1,334 MiB，分组渲染自身约 62 MiB；预估容量的一次分配替代了多次字符串增长。runtime 的精确累积分配增量是定量结论，pprof 数字是默认采样估计，二者不要求逐字节相等。

CPU 采样中 `madvise` 从 3.97→2.22 秒、`memmove` 从 0.38→0.17 秒；静态 URL 避免反复替换后，`stringslite.Index` 从 1.31→0.10 秒。`syscall.rawsyscalln` 3.50→3.41 秒基本不变，剩余必要 I/O 不能靠比例下降推断消失。密码校验的 Argon2 初始化采样分配两版均约 1,729 MiB，因总分配下降，其占比上升；没有减少密码校验强度。URL 安全检查仍保留。

实现集中在内容视图和渲染：先在不可变缓存中选择公共/管理员视图，再为调用方克隆一次；分类读取直接检查当前父分类 ACL；分类渲染保存索引而非复制完整书签，并直接写入一个 builder；按实际命中量预留容量且上限 8 MiB；builder 归还池前 Reset；静态 URL 跳过无必要的动态替换。模板临时缓冲池另设 **256 KiB 保留上限**，大响应仍完整返回，使用后不把大型 backing array 长期留在该池。

认证、会话存储及 test wrapper 的相关源文件摘要在优化前后相同，见 [优化前来源](../../metrics-reports/admin-resource-analysis-2026-10-27/source-before-sha256.json) 与 [最终来源](../../metrics-reports/admin-resource-analysis-2026-10-27/source-final-sha256.json)。本轮没有修改认证强度、撤销检查或授权边界。

## 内存权衡及中间版诊断

中间 v1 已减少分配，但正式轮次一次强制 GC 后 HeapAlloc 为 26.82 MB，优化前为 9.39 MB。没有据此直接宣称泄漏或忽略上涨：暂停后续饱和测试，检查 heap，发现模板 `bytes.growSlice` 和 HTTP byte buffer 是主要保留项，未发现首页 builder 保留大型数组。随后增加模板池上限并重新完成全部最终轮次。中间版原始数据与 profile 保留，不能当成最终版成绩。

同样的 15 秒、45 次读取和 8 次探针诊断中，优化前连续三次 GC 后 HeapAlloc 为 17,382,952 / 9,193,216 / 9,194,416 字节，最终版为 21,274,096 / 10,290,440 / 10,289,032 字节。第一次 GC 后池中的 victim 对象会影响读数；第二、第三次读数接近。因此，不能将不同轮次一次 GC 的全部差值归功于模板上限。

第三次 GC 后最终版比原版多 **1,094,616 字节，即约 1.044 MiB**。结合 heap 中公共可见视图约 1.21 MiB 的采样归因和代码，这是保留公共视图缓存带来的约 1 MiB 成本的证据；差值本身不能证明每一字节都来自缓存。该成本针对本夹具和当前不可变快照，随可见条目数量变化，不是所有部署固定增加 1 MiB。这些短诊断也不能证明永远不会泄漏。最终正式 profile 一次 GC 后 HeapAlloc 为 10,388,728 字节，优化前 9,391,048 字节。最终版降低了本轮原生及饱和 RSS，但没有声称所有存活堆指标都下降。

## 回归、复现与证据

数据测试覆盖调用方修改隔离、并发编辑时 apps/bookmarks 配对一致、父分类收紧 ACL、只加载所需集合。渲染测试覆盖八种精确 HTML、动态 URL 转义和危险协议、父分类私有与图标、输入和先前响应不被修改；八个 golden 又与冻结的旧渲染器独立比对，来源见 [provenance.json](../../internal/pages/home/testdata/navigation-render/provenance.json)。模板测试覆盖大型 backing array 丢弃、小缓冲复用、模板失败原子性、大响应及 writer 错误。

最终构建已通过完整 Go 测试、九个核心包 race、Linux amd64/arm64 交叉构建、[24 项浏览器回归](../../metrics-reports/admin-resource-analysis-2026-10-27/final-browser-regression.json)、[15 项出站行为回归](../../metrics-reports/admin-resource-analysis-2026-10-27/final-outbound-regression.json)、[7 组真实升级恢复回归](../../metrics-reports/admin-resource-analysis-2026-10-27/final-recovery-regression.json)。本轮七项 Python harness 测试覆盖零等待队列上限、错误释放并发容量、CPU 时间解析及实际私有卡片判断。

全部 JSON、CPU/alloc/heap profile、pprof 文本及三个阶段源文件摘要保存在 [证据目录](../../metrics-reports/admin-resource-analysis-2026-10-27/)。其中 `native-*-3rps-180s.json` 是原生等速率数据，`profile-*-3rps-180s.json` 是相同 wrapper 的定量数据，`retention-*-15s.json` 只解释池的 GC 阶段；6 请求/秒校准及部分中止记录明确排除出正式配对结论。运行方式见 [压测说明](../../tools/security-load/README.md)。

结论范围仅限本机这组顺序配对实验。没有重复样本置信区间，也没有据此宣称 NAS、低端 ARM、真实 Docker 限额或物理断电性能；历史 30 分钟登录压力记录保持原样，不能用本轮三分钟代替。
