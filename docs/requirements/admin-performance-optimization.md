# 管理员读取持久化开销优化验收

日期：2026-10-27，开发机 Apple M5 / 10 CPU / 32 GiB / macOS arm64。该专项配对比较具有相同 ACL 语义的优化前后构建，区别于早前不具备真实私有授权的旧版 0.6.7 比较。

## 测量前约定

优化前构建固定为 `/tmp/flare-phase1-final-candidate`，SHA-256 `b0ffcb369d3f5f149baa46ced5d4ee37c9a1476a89c4ed7b4a61e02d12b072cf`。保留原文件，不用新构建覆盖。使用 [已有冻结预算](scale-acceptance.md)：热首页 p95 < 3 秒，搜索 p95 < 1 秒，RSS < 1 GiB；不在得知优化结果后重新定门槛。

夹具仍为 20,000 条、100 分类、10,000 私有，上传/配置原始摘要 `9537f2d51a70b2944ccbe6945eabdef698d6900326e2ee4d0c444d14c310214b`。两轮各实际运行至少 **180 秒**，同机顺序执行，独立全新工作目录与端口，配对轮次期间不进行构建或其他性能负载。执行器相同，实际摘要写入 JSON。

四个固定读工作者共享一个管理员会话，各自交替请求完整首页与仅命中末尾私有条目的搜索。每个响应必须 200 且包含预期私有名字。另一个有界工作者约每两秒执行：真实正确密码登录→读取私有条目→带 CSRF 退出当前会话→用退出前 Cookie 重放，确认不再包含私有名字。探针只撤销自身会话，不撤销四个读取工作者共享的管理员会话。

CPU/RSS 每两秒采样，另记录内核子进程 RSS 高水位、各路径 p50/p95、成功数/错误数、合计吞吐和隐私断言。完整内核 fsync 次数不从两秒文件采样猜测；同步提交次数以独立可控写入计数测试为证据。优化前后各测量 180 秒，用于性能对比；早前的 1,800 秒测试用于登录稳定性验证。两者的负载和目的不同，均未覆盖低配 NAS。

## 执行器预演与排除项

第一次 180 秒预演期间，同机存在约 10 秒的并发存储测试及 race 检查负载，因此该轮仅作为[诊断记录](../../metrics-reports/admin-read-optimization-2026-10-27/diagnostic-before-interference.json)，**不计入公平配对对比**。预演还暴露了执行器断言问题：公共搜索页会回显查询词，不能把查询词存在等同于私有卡片泄露。该轮 `privacy_violations` 是这个过宽断言产生的假阳性，不能作为产品泄露结论。

正式执行器改为匹配实际 `<span>PRIVATE Entry 19999</span>` 卡片，并要求撤销后重放 HTTP 200 且不含该卡片。增加“搜索框回显不算可见卡片”“HTTP 200 缺少授权卡片必须记录失败”的测试；四个 Python 用例通过。3 秒预演 20 次管理员读取均 200，登录/撤销/重放探针通过，零断言失败。此预演不代替两轮各 180 秒正式压力。

正式配对执行器 SHA-256：`b763de7217b534af8cc1c975d9576d305c46a0d534c4daba4ac5c678039a8739`。

## 变更与安全约束

此次优化复用的是单个请求的鉴权证据。入口 `SessionSnapshot` 建立持久化授权点；请求内 `GuardSession` 绑定 Store、token、generation 和单调时间起点，每次仍检查当前撤销状态、有效会话映射、存储故障及最新持久化时间边界。短请求重复检查不再重复读取墙上时钟或提交同一安全状态；证据超过一秒会通过持久会话检查刷新，新请求重新建立证据。

成功 GET/HEAD 在释放响应前仍执行新的持久化会话校验。HEAD 校验不延长空闲期限。渲染过程中发生撤销，已经准备的私有正文被丢弃并返回 401；存储故障返回 503。写入、导出、最近认证仍保留相应的新鲜校验及授权排序。入口和输出前的必要落盘保留，因此普通管理员读取仍有持久化成本。

提交时验证已有实例完成标记，正常提交复用已持久化的不可变标记，省去每次重写它的步骤。初始化及恢复重放仍按协议写入标记；标记缺失或被替换时，在发布新日志前关闭业务并报故障。没有调整 Argon2 参数、条目权限、CSRF、会话撤销或恢复策略。

## 正式配对结果

正式比较期间未运行其他构建、测试或压力负载；受干扰的预演未纳入对比。优化前 **09:02:59–09:05:59（Asia/Shanghai）**，实际 **180.246 秒**；优化后 **09:06:02–09:09:02**，实际 **180.156 秒**，顺序执行，没有缩短采样时间。

优化后构建 SHA-256：`4396a134ca328ea60f7ac1ad3bc79701fea366c6aa2c6311096a4fa2e2140d45`。两轮夹具、工作负载及执行器摘要完全相同。原始数据：[优化前 180 秒](../../metrics-reports/admin-read-optimization-2026-10-27/before-180s.json)、[优化后 180 秒](../../metrics-reports/admin-read-optimization-2026-10-27/after-180s.json)、[逐项机器判定](../../metrics-reports/admin-read-optimization-2026-10-27/verdict.json)。

- 管理员首页 p50/p95：**387.10 / 504.86 ms → 213.67 / 287.56 ms**；p95 下降 **43.04%**。
- 管理员搜索 p50/p95：**384.04 / 501.77 ms → 185.34 / 257.82 ms**；p95 下降 **48.62%**。
- 合计读取吞吐：**9.210 → 18.451 请求/秒，2.003 倍**。优化前首页/搜索各 830 次；优化后分别 1,661 / 1,663 次，**全部 HTTP 200**，每次包含应授权的私有卡片。
- 独立正确密码登录→当前退出→旧 Cookie 重放探针：优化前 **42 次**、优化后 **63 次**，登录全部 303，退出及撤销后隐私断言全部通过。探针记录的登录 POST p50/p95 为 **256.84 / 287.73 ms → 61.48 / 128.32 ms**；这些不是完整探针链路的端到端延迟。两轮 **零隐私断言失败、零请求异常**。
- 内核 RSS 高水位 **155.09 → 224.48 MiB**，增加 **69.39 MiB**；两秒采样各 89 个，`ps %cpu` 均值 **22.75% → 40.96%**。本轮同时观察到吞吐提高及 CPU/RSS 增加，未用分配剖析证明它们的因果关系；不宣称内存下降。两轮均低于事前 1 GiB 上限。

热首页、搜索、资源上限及实际成功/私有边界断言均通过，延迟与吞吐有可测改善。这是四工作者的三分钟配对实验；它不代替历史冻结构建的完整三十分钟测试，也不代表低配 ARM/NAS、受限容器或无限运行时间的性能承诺。

## 回归与计数证据

新增安全回归包括 [7 个 Store 测试](../../internal/security/session_proof_test.go)及 [6 个请求身份测试](../../internal/auth/request_identity_test.go)：新请求不复用旧证据、同请求重复校验、即时撤销、Store 绑定与关闭/故障、最新持久时间过期与删除、长请求刷新、输出前时钟回拨、最终持久化失败、GET/HEAD 准备正文后撤销、匿名坏 Cookie 保持公开读取、HEAD 不延长空闲期，以及完成标记复用和损坏拒绝。

可控计数测试证明 **50 次 `GuardSession` 不增加墙上时钟观测或安全文件写入**；另一个 HTTP 测试每请求调用 75 次身份辅助函数，期间安全状态字节不变，且新请求获得新证据。初始化完成标记只写一次，后续创建会话/撤销不重复写，损坏标记不会发布新的提交日志。**没有测量完整 HTTP 请求的所有内核 fsync 次数，因此不提供虚构的整请求 fsync 下降百分比。**

最终补强后全量 `go test -p 1 ./...` 通过；八个核心包 race、认证定向回归、Linux amd64/arm64 交叉构建通过。当前提交协议真实进程强杀矩阵为 8 个边界（启动 3 / Store 初始化 3 / 撤销 2），成功重放或关闭业务；不将其称为物理断电。
