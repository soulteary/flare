# Flare 登录与私有访问：阶段一实施规格

版本：v1.1（YAML 兼容与自动迁移版）
日期：2026-10-27
现状基线：Flare 0.6.7；下文为待实现行为。
关联文档：[需求说明书 v1.2](login-private-access.md)

## 1. 范围与替换说明

本文完整替换 v1.0 规格。保留 apps.yml、bookmarks.yml、config.yml 作为事实来源，保持编辑器保存和手工改文件后重启的操作方式。不要求内容入库、schema_version、条目 ID、visibility、revision 或额外内容应用命令。内部冲突控制和安全状态不能变成用户必填配置。

首阶段只有匿名与一个管理员；没有空间、所有者、成员、分享、注册或外部身份模型。不提供长期记住设备、设备列表、网页完整备份与网页恢复令牌。REQ-SHARE-01、REQ-SHARE-02、REQ-SHARE-03、REQ-USER-01、REQ-USER-02 后置，无需为其实现存储。

以下 SPEC-01–SPEC-10、T01–T30 均为阶段一 P0；仅一键匿名预览、详细配置来源面板为 P1。内部文件名、端点和命令均为设计接口，不代表当前版本已支持。实施期间变更行为须同步两份文档与用例。

## 2. SPEC-01：YAML 与日常使用契约

### 2.1 内容来源与字段

三个现有 YAML 文件仍是唯一内容/设置来源，编辑器继续写回对应文件；手工修改 apps.yml/bookmarks.yml 后重启，config.yml 沿用现有读取/缓存机制。外部涉及访问范围变化时建议停写后重启，避免混用新旧导航快照；不要求额外 CLI。

只增加分类可选布尔字段 private，条目继续使用原 private；应用仍使用 links、无分类。不改变 name/link/icon/desc/category 和分类 id/title 的现有意义。不自动重排、补 ID、加版本、改已有 private 值或把内容导入状态库。

```yaml
categories:
  - id: public-links
    title: 公共导航
  - id: internal-links
    title: 内部导航
    private: true
links:
  - name: 公共链接
    link: https://example.com
    category: public-links
  - name: 私有链接
    link: https://internal.example.com
    category: public-links
    private: true
  - name: 继承私有分类
    link: https://another.example.com
    category: internal-links
```

缺省/false 只表示本级没有附加限制；父分类 true 时子项 false 仍然私有。无分类条目与分类缺省保持旧公开语义，不按“文件里新增一行”自动改变默认值。

编辑器新建分类/无分类条目默认私有并实际写 private: true；分类内条目默认继承，分类公开时显示“保存后匿名可见”。新建与既有条目打开表单不是同一操作，不能保存旧公开条目时无意改私有。分类私有在匿名页面连标题都不输出。

未知扩展字段用 YAML 节点级读改写保留，不能普通结构体反序列化后覆盖丢字段。保留语义不承诺保留注释/空格；自动迁移完全不改原文件字节。既有锚点、别名及合并键按解析器有效值只读兼容，最终 private 值仍严格校验，循环和超限展开拒绝；含锚点/别名的文件网页编辑或导入覆盖明确返回只读错误，继续允许手工修改并重启及原始 YAML 导出，不自动展开共享节点。已知 private 接受 true/false/缺省，字符串、数字或 null 拒绝；近似拼写如 privte 给出明确告警，不算已启用保护。重复已知映射键拒绝，不能让检查器与业务采用不同值。

已有重复分类 ID、悬空 category 或非法 private 可能导致权限误判，进入配置待修复，不把条目落到公开根。无类别的合法 category 缺省保持原用法。应用不接受 category 引用作为私有继承捷径。

### 2.2 文件保存与冲突

沿用逐文件写入：锁内重新读磁盘→校验会话与请求摘要→验证完整目标内容→备份→同目录暂存/sync/原子 rename→发布新内存快照。原摘要以服务器读取的完整文件字节计算，放在隐藏表单字段/请求中，不写 YAML。无摘要 400，陈旧摘要 409；GET 不写入。

失败保持原文件和有效快照，磁盘提交后内存发布失败则停止该业务入口，重启从磁盘重建；不使用旧授权快照继续输出。备份必须先成功。只读 YAML 可浏览，保存/导入 503 并显示只读原因，不把内容转到另一个可写副本假装保存成功。

每个请求使用同一不可变内容/权限快照；网页保存后续请求立即见新策略。手工外部写入必须按现有说明重启生效，不保证与运行进程并发写。只支持单写实例，自动检测明显的共享实例锁冲突；不宣称锁能阻止运维直接改文件。现有编辑器跨两文件保存保留其暂存、版本校验和回退副本流程，不宣称跨文件事务；异常保留恢复副本并停止覆盖，断电可能需要按提示恢复。新增跨 apps/bookmarks 移动不提供原子保证，采用明确导出/导入与删除两步，不能先删后导入。

## 3. SPEC-02：访问模式与新旧实例识别

### 3.1 旧配置继续生效

保留 FLARE_DISABLE_LOGIN、FLARE_VISIBILITY、原 CLI 别名、FLARE_USER、FLARE_PASS 和既有优先级。来源追踪必须在默认值填充和 fail-closed 纠正之前记录，才能区分“原始矛盾配置”与“新解析器已纠正的值”。不增加与 Visibility 竞争的站点模式变量。

启用登录（DisableLogin=false）时：DEFAULT 匿名只读公开内容，管理需管理员；PRIVATE 全站导航和管理需管理员。DisableLogin=true + DEFAULT 为可信免登录内容管理，不伪装成认证用户。true + PRIVATE、非法 Visibility、非法布尔值均拒绝业务启动，退出非零并指出配置项和来源，不回落公开。

运行参数仍是站点模式事实来源，用户在 Compose/.env/CLI 修改并重启后生效；网页只呈现有效值与修改方式，首阶段不提供一个会被参数覆盖的网页模式开关。网页资源公开变化需近期密码验证与确认；本地文件修改以数据目录访问权和运维停写重启授权。

### 3.2 识别证据和状态

- `new`：无完成标记/内部状态、无可信旧安装证据；仅初始化说明，业务 503，无导航数据。
- `migrating`：有旧部署证据、首次建立安全状态；只读检查并自动迁移，成功即 ready，不常态停留等待用户批准。
- `attention_required`：缺凭据、免登录与 private 冲突、无法区分纯默认样例等；通用提示，不输出业务数据，给准确本地处理路径。
- `ready`：安全状态及内容有效，按原模式服务。
- `faulted`：完成标记存在但内部状态丢失/损坏、持久化失败或迁移损坏；业务 503，不能作为首次安装/旧默认重建公开实例。

旧安装证据为存在用户非样例内容、历史安全文件（如旧 Cookie 密钥），或显式访问模式参数与旧文件组合；仅有用户名/密码和发行样例不足以证明已安装，避免新部署只提供密码却意外继承旧免登录默认。不能只因发行镜像内置了三个默认样例就判旧实例。发行包提供样例摘要识别，用户内容仅用于比对不外发。不声称能辨别完全相同的旧默认样例与新样例；无其他证据时提供 `flare security adopt-legacy-defaults` 本地显式选择保留旧可信行为，仍检查没有 private=true。

新实例无显式设置时默认启用登录、PRIVATE；保存“新安装安全默认”来源标记，后续重启继续采用该默认，不重新套用旧免登录默认。显式配置仍优先；新用户明确 false + DEFAULT 可初始化公开导航，明确 true + DEFAULT 可初始化可信模式（无私有标记），无需被强制建立闲置账号。不会仅凭显式免登录参数就绕过新安装的本地/启动配置授权检查。

### 3.3 可信兼容

可识别的旧 true + DEFAULT 且无 private=true：自动 ready，保持原匿名内容读写；若来自旧默认，启动摘要标明“继承旧默认，意图未知”。不得写成“安全配置已确认”，不得悄悄改为公开只读。

任何分类/条目 private=true 与免登录并存：attention_required，全业务暂停，不部分显示或忽略私有标记。处理选择：在源配置开启登录并提供管理员凭据，重启自动继续；或停机逐项检查并移除不需要的 private 标记后重启。没有一键自动清标记。可信模式下网页保存、导入若将引入私有标记，整次拒绝并提示先开启登录。

从认证切到免登录仍做同样检查；未变更的安全状态可保留供以后恢复，但全部会话撤销，匿名不能访问账号/安全管理。免登录内容写入仍要求 CSRF/来源校验，不代表公网上安全。

## 4. SPEC-03：内部安全状态与凭据来源

### 4.1 必要持久化

默认在现有数据工作目录创建 `.flare-security/`（目录 0700，秘密文件 0600），可选 FLARE_STATE_DIR 改位置。只保存单管理员哈希、会话摘要/状态、实例 ID、安全世代、迁移来源/输入指纹、时间高水位与安全事件；不保存导航内容副本，不建立空间/成员 ACL 表。实现可用本地嵌入式事务存储；ADR 固定格式/依赖和各架构构建，在实现前验证以下故障契约，不向用户暴露数据库操作。

建立独立完成标记及带校验的迁移提交日志；实例 ID 对照，缺一不当新实例。写成功必须持久落盘；原子改密与全会话撤销、并发 init、正常重启、损坏检测均可故障注入验证。启动和停机 CLI 取独占实例锁；多副本/网络盘共写不支持。

已有整个工作目录持久挂载且可写，升级自动创建目录；只挂载 YAML 文件的用户须新增该目录挂载。启动说明标明路径及持久化要求；应用不能可靠检测任意容器挂载，不能宣称已自动验证挂载持久性。运维须做重建容器验收。路径不可写拒绝迁移，不改用临时目录。全目录被删除无法识别历史，应在部署文档明确是数据丢失而非恢复方案。

### 4.2 来源模式的兼容选择

界面仅呈现“部署配置管理密码”或“应用管理密码”。内部模式 `deployment`/`local` 保存在安全状态中，普通升级不用增加配置字段。

- 首次自动迁移显式、有效旧 FLARE_USER/FLARE_PASS（或新增密码文件）：默认选 deployment，保留 Compose 修改凭据的旧工作流；若运维已显式选择 FLARE_CREDENTIAL_MODE=local，首次迁移按 local 建立，并在摘要说明以后不跟随部署密码。
- 新安装用部署密码作为初始输入，默认 local；如需持续托管，可选高级 FLARE_CREDENTIAL_MODE=deployment。该项仅初始化/明确切换使用，普通用户不必填。
- deployment 每次启动读取旧优先级后的有效来源，同值不改写，不同用户名/密码验证成功后原子更新并撤销全部会话；网页直接改密拒绝并说明来源。
- local 启动以内部哈希为准；遗留环境密码不重设账号。用户显式确认“以后在应用管理密码”并验证当前密码后，可由 deployment 转 local；记录来源切换，撤销旧会话，建立新当前会话。提示以后修改旧 Compose 密码不会生效。
- local 转 deployment 只允许停机显式命令，不仅凭环境变量变化静默切换。FLARE_CREDENTIAL_MODE 与已存模式矛盾时拒绝启动并指出使用切换命令，不能忽略运维的明确指令。

deployment 缺失/空/不可读密码源拒绝受保护业务，不生成随机密码、不回退旧值；local 下遗留文件不存在仅脱敏提示，不因没读取的初始化文件而锁住用户。有效阶段同一凭据明文+文件并存拒绝；local 已初始化后的遗留双输入忽略并警告，不参与凭据计算。

新 FLARE_PASS_FILE 支持只读 Secret；最多 514 字节，UTF-8，只删一次末尾 LF/CRLF 后验证，其他空白不删。新设密码规则为 15–128 码点、最多 512 字节；旧迁移/旧 deployment 源非空密码按原值接受，不强制改密。旧 FLARE_PASS 原字节比较兼容，不无故按新 Secret 文件格式处理；账号与密码提交的认证请求体上限 8 KiB，超过 413，源密码超过可接受请求长度则预检明确失败，不截断。新存储 username 非空，至多 256 字节；部署用户名缺省/空继续使用旧默认 flare，非空值迁移保留旧精确登录名（无额外 trim/大小写转换）。异常超长旧输入须预检报错，本地重设，不自动截断。

### 4.3 密码、初始化和恢复

使用成熟 Argon2id 库，初始 m=19456 KiB/t=2/p=1、独立随机 salt 16 字节、结果 32 字节，参数随哈希存储；并发 1、等待队列最多 8，等待最多 10 秒，超限 429/503，不自动降级快速散列。不存在用户名做同成本虚拟校验。新设密码匹配离线版本化常见弱口令表，旧弱密码只提示不限制导航。

`flare security init [--username NAME] [--password-file PATH]`：停机或启动前，持锁，仅新状态/明确 attention 状态允许建立管理员；终端两次隐藏输入密码，无密码参数，无远程首访建立账号。部署已提供有效凭据可在启动前自动 init。完成后按新安装安全默认/显式参数运行。

网页改密验证当前密码和 CSRF，哈希更新与全撤销同事务；成功签发新当前会话。写 Cookie 失败不回滚密码，提示用新密码登录。所有日志、页面、URL 不出现明文或哈希。

`flare security reset-password [--password-file PATH] [--take-local-control]`：停机有目录权限，隐藏输入或文件设新密码；local 原子改密、撤销会话；deployment 默认拒绝并提示改源，只有显式 take-local-control 才转 local。缺失旧密码但尚无完整账号的 attention 状态也允许此命令：以已记录的旧有效用户名（缺省 flare）建立单管理员 local 状态，保留原站点访问模式并完成迁移检查；不能覆盖已完成而损坏的库来绕过恢复。没有网页恢复令牌、邮件或关认证恢复步骤。

## 5. SPEC-04：授权、快照与所有输出

local/deployment 登录模式仅匿名与管理员。匿名可读当且仅当：站点 DEFAULT ∧（无分类或分类 private 不为 true）∧ 条目 private 不为 true。管理员读取全部合法资源，管理全部单用户内容。分类自身有独立读取判断；不显示私有分类名、隐藏项数或占位符。站点 PRIVATE 先挡匿名。可信免登录模式按 SPEC-02 规则，不能含有效私有资源。

私有性由每次内容快照的 YAML 计算，不附加独立 ACL 库；网页修改或进程重启重建全量索引/跳转映射。请求选择旧条目位置时必须携摘要，锁内重新读当前文件，不能保存时错指向重排后的另一项。读链接可用服务端按快照生成的不透明句柄；失效句柄 404/重新加载，不要求给原 YAML 加稳定 ID。

全部入口登记为公共静态、认证流程、授权读取或管理写入：导航、应用、分类、搜索/联想、计数、分页、错误、原始数据、跳转、图标、导入导出及备份下载。先授权过滤再计数/序列化。无权和不存在统一通用 404，不输出私人标识；未认证管理 API 统一 401，管理查找在认证之后。

历史 Base64 跳转匹配当前有权条目；没有可授权匹配就 404，不按编码参数直接跳。公开和私有副本同 URL 时公开副本可以继续跳转，但不揭露私有副本。原始跳转 URL 已携目标的历史事实无法撤回，代理日志需脱敏，不宣称升级可以从用户历史中删除 URL。新生成跳转避免把私人明文 URL 放进请求路径，默认 no-referrer。

私人/身份差异 HTML、JSON、登录、错误、导出、备份默认 Cache-Control: private, no-store，禁用跨用户 ETag/304；S1 可直接不发这些响应的 ETag。旧 If-None-Match 仍校验当前权限，不能返未授权 304。通用内置图标可公开缓存。

保持现有文本/属性转义和 URL 协议允许表；private 不影响输入安全。导入不抓取链接/图标。首阶段不新增图标代理；现有抓取若保留必须授权并防私网/元数据 SSRF、重定向与 DNS 重绑定，否则关闭入口。私人图标不发到匿名 DOM/预加载，不自动调用外部 favicon 服务。外部搜索只在用户明确提交后外发查询。

## 6. SPEC-05：普通会话与安全写入

Cookie 至少 32 随机字节不透明令牌，服务端仅摘要；持久记录创建、最近有效活动、12 小时绝对期限、近期密码验证、撤销与安全世代。闲置 30 分钟失效；只有前台导航和成功业务操作续闲置，后台天气/时钟/轮询、静态、健康检查不续期。不用前端心跳绕过绝对期限。

登录成功与重新认证轮换令牌；近期验证不延长原绝对期限，首次密码登录算近期验证。改密/凭据来源切换、公开私有资源/分类、敏感导出要求 10 分钟内验证密码；缺失返回 REAUTH_REQUIRED 后回确认页，不自动重放写请求。手工停机改源配置以本地目录控制权授权，不要求网页会话。

当前退出只撤销当前，全部退出撤销所有且不签发替代；改密/凭据源变化/恢复/首次迁移废止全部旧会话，重启不重复注销。服务端每请求检查撤销和世代，写操作锁内/提交前再校验；撤销提交前已发送字节无法撤回。普通重启保持实例身份、Cookie 名和未过期会话。多标签页仅界面同步增强，不依赖前端判权。

Cookie：host-only、Path=/、HttpOnly、SameSite=Lax，直接 TLS 或配置 HTTPS 时 Secure；实例随机持久标识加入名称避免相同内部端口冲突。不提供长期记住设备。浏览器会话 Cookie 的恢复功能不改变后端期限。不同端口不是主机级安全隔离，推荐不同主机名。

状态存储维护持久时间高水位；检测时钟回拨超过 60 秒时撤销全部会话再重设时间基准，失败 faulted；小回拨时间钳制，过期/撤销不可复活。写入和跨重启行为用可注入时钟验证。

登录、改密、退出、重新验证和所有内容写请求用绑定会话/预认证状态的 CSRF Token；可信免登录的内容写入使用独立浏览器预认证 CSRF 状态，不能赋予安全管理身份。有 Origin 必须匹配，缺失再查 Referer；都缺失时仅有效 Token 且 Fetch Metadata 非 cross-site 才接受，缺 Fetch Metadata 本身可回退；Origin:null/明确跨站不得靠 Token 放行。无脚本表单也携 Token。

## 7. SPEC-06：导入导出、页脚和 HTTP

### 7.1 保持现有导入工具

沿用现有 categories/links、8 MiB 输入、合并后 20,000 项/分类、32 层浏览器文件夹上限，预览 15 分钟或重启失效。仅作用选中的一个文件，导入前备份沿用 `.flare-bookmark-backups/` 和下载入口。没有更换导入格式/限额的隐含需求。

重复识别继续目标分类+规范化比较 URL；默认跳过，可选择更新名称/非空图标描述或全部保留。重复更新不得清条目 private，也不得把目标分类 true 改 false；不自动合并不同分类的权限。原生 YAML 读写保留分类/条目 private 与其他扩展字段。

登录模式导入新增书签默认新私有分类，应用新增项默认 true；管理员可在预览中显式选择公开目标/公开导入，展示新增公开数量，需近期密码验证。已有私有状态不允许被导入的 false/缺省清除；要放宽使用独立编辑确认。可信模式只能导入纯公开内容，预览明确“保存后匿名可读写”，含 true 则拒绝；不能套用登录模式的默认私有后自动去标记。

预览不信任客户端结果，绑定会话（可信模式为预认证浏览器状态）、目标文件摘要、选项和输入摘要；提交时重新验证，过期/磁盘变化 409，无部分写入。不得因解析旧文件就把缺失内容集合初始化成公开数据。

YAML 导出保留私有语义，不含账号/会话；HTML 无权限语义，显示“重新导入其他工具可能失去保护”。导出及历史备份下载需当前管理员或明确可信模式，私人导出要求近期验证和确认；流开始前再授权。禁止导出接口不阻止复制已能阅读的数据。

### 7.2 公开页脚与输入

保留现有 config.yml 外观/搜索/内部 HTML 页脚行为；不整库迁移设置。新增可选独立公开登录页脚字段 `LoginFooter`，值为文本或安全过滤的 HTTP(S) 链接 HTML 字符串，缺省空，不自动复制现有 Footer。旧版本忽略该新增字段，但升级前备份仍保留原文。

公开站点导航原 Footer 继续按管理员可信 HTML 使用；私有站点只有登录后导航加载原 Footer，登录/错误/初始化页面不加载它。私人信息若被管理员放在公开导航 Footer 属主动公开边界，不能宣称系统识别其含义并自动脱敏。普通书签输入始终不享有 Footer 的可信脚本能力。

### 7.3 现有路由适配与响应

沿用现有登录/编辑/传输路径，通过同一认证和授权服务修正；不为首阶段强制另建全套 REST 资源接口。实现 PR 交付路由登记清单，每条注明主体、动作和 CSRF/输出过滤；旧路径不能保留旁路。新增改密、重新认证、退出全部及基本安全状态入口，路径在实现路由清单中冻结并与测试绑定。网页表单和 JSON 如并存必须使用同一服务。

JSON 错误为 `{error:{code,message},request_id}`；400 INVALID_INPUT/INVALID_PRIVATE/INVALID_IMPORT，401 INVALID_CREDENTIALS/AUTH_REQUIRED/SESSION_EXPIRED，403 FORBIDDEN/SOURCE_REJECTED/CSRF_INVALID/REAUTH_REQUIRED/CREDENTIAL_EXTERNALLY_MANAGED，404 RESOURCE_NOT_FOUND，409 FILE_CHANGED/PREVIEW_EXPIRED，413 PAYLOAD_TOO_LARGE，429 RATE_LIMITED（Retry-After），503 STORAGE_UNAVAILABLE/INSTANCE_NOT_READY/CONTENT_READ_ONLY。未知用户与错密码同文案/状态。页面未认证 302 登录；成功写入/登录 303，GET 不写入。存储故障不作为匿名继续处理。

return_to 只允许应用内允许页面的单斜杠相对路径，拒绝绝对/协议相对 URL、反斜杠、控制字符、重复解码混淆、敏感认证路径，非法回首页。Cookie 往返失败最多一次跳转后显示通用诊断，不泄漏秘密/内部路径。不实际保留草稿就不提示已保留，私人草稿不入 localStorage。

## 8. SPEC-07：代理、日志和低配部署

保持 FLARE_COOKIE_SECURE 等现有配置。FLARE_EXTERNAL_URL、FLARE_TRUSTED_PROXIES、FLARE_ALLOWED_HOSTS 仅为复杂反代可选项，不要求普通用户全填。简单保留 Host 代理可沿原 cookie_secure 使用，直连按实际 TLS；Host 必须合法，配置规范域名时拒绝不在允许列表的 Host。

显式受信代理才解析 X-Forwarded-For/Proto/Host，从最近代理向外逐跳找到第一个不可信来源；任意不可信请求的头不采用。S1 不同时解析 Forwarded 避免冲突；头值非法/矛盾不猜测。显式规范外部 URL 不被头覆盖，来源规范化 scheme/主机/默认与非默认端口/IPv6。要求 Secure 却用 HTTP 不降级 Cookie，给通用排查信息。代理示例清除客户端伪造头。

账号与 IP 各自滚动 5 分钟 10 次失败后冷却 30 秒，连续触发倍增上限 15 分钟；冷却期间不哈希，不延长冷却，连续 15 分钟无失败重置。正确登录清账号计数不清其他用户共享 IP 失败；失败计数/桶最多 10,000，超限拒绝新增请求并清过期桶，不无限分配。来源 IP 必须可信。哈希并发/队列见 SPEC-03，不能公网永久锁账号。

基本诊断只管理员见有效模式与来源、密码来源、状态路径可写、Cookie 参数、实例 ID、实际版本；未登录只看通用错误。详细来源面板 P1。日志仅事件类型、结果、时间、request_id及脱敏来源，不记录密码/散列/Cookie/token/私人 URL/请求体；访问日志按模板隐藏敏感查询。历史 Base64 链接的代理访问日志风险在升级文档说明。迁移报告只默认显示数量/来源，不公开内容和密码。

## 9. SPEC-08：自动迁移算法和兼容分类

### 9.1 用户升级操作

1. 记录旧镜像标签与摘要或保存旧二进制，保存 Compose/.env/启动参数及挂载关系。
2. 停止实例，完整备份工作目录（含三个 YAML、旧 `.flare-cookie-secret`、已有备份和隐藏文件）；Secret 单独安全保存。仅导出书签不是完整备份。
3. 保持 YAML/账号/访问参数。整个工作目录挂载无需增加内容配置；逐文件挂载补充 `.flare-security/` 的持久可写挂载，或可选 FLARE_STATE_DIR。
4. Docker 更新镜像并重建，二进制替换后按原参数启动。程序自动预检和迁移；用户无需默认执行 migrate 命令。
5. 检查脱敏启动摘要，正常完成后重新登录一次。用独立匿名窗口/无 Cookie HTTP 检查首页、搜索、旧跳转、编辑器、导出，不用管理员视角猜测保护。
6. 重建容器再验证账号/会话与内部状态持久化，确认后开放公网。失败按具体状态处理，不关闭认证排障。

### 9.2 首次启动顺序

取得实例锁→读取原始配置来源与内容（不写）→识别新旧→验证访问组合/全部 private 与引用→读取旧有效凭据→检查状态目录→创建迁移快照/提交日志→哈希凭据并建立实例和会话世代→持久完成标记→构建授权快照→监听业务请求。任何预检失败不给内容响应。

首次迁移快照放入 `.flare-security/migration-backups/<id>/`，目录 0700，记录迁移版本、脱敏有效来源、模式、YAML 字节摘要、旧安全文件副本及变更清单；三个原始 YAML 按字节复制，原文件不写。外部 Secret/Compose 不自动收集；标注需运维备份。快照失败不得提交迁移。不要将快照误称为可独立恢复整个 Docker 部署的备份。

迁移变更只有新内部安全材料和完成标记，不改 YAML、.env、CLI 或旧 Cookie 密钥。先构建暂存状态、校验并 sync，提交日志记录阶段，再发布完成标记；断电启动按日志完成或退回未提交状态。完成标记有而库缺失为 faulted，不重新从旧密码建库。备份已有有效副本不能被失败重试覆盖。输入在迁移期间变化则中止重读，不能混用两套文件。

### 9.3 分情况自动行为

- 旧 false + DEFAULT、有效源密码：自动保持公开站点+管理员编辑，选 deployment；private=true 条目开始对匿名隐藏，输出收紧数量。
- 旧 false + PRIVATE、有效源密码：自动保持全站私有，资源 private 缺省不改；未来用户手动改站点公开会使缺省条目公开，切换说明必须提示影响。
- 旧 true + DEFAULT、无私有标记：自动保持旧可信公开读写，来源显式或继承默认分别标明；没有管理员不生成假账号。
- 旧 true + DEFAULT、有私有标记：attention_required，提示分类/条目数量（仅本地报告），给开启登录或逐项改文件的路径。
- true + PRIVATE、无效 Visibility/布尔值、重复凭据来源：配置错误，指出原始来源，不能用纠正后的派生值假称迁移成功。
- 旧登录启用、无有效密码：attention_required，不能恢复仅在历史日志中的随机值。停机 reset-password 建立 local 密码，或补 FLARE_PASS/FILE 源再启动；原访问模式保留，不放开站点。
- 旧短密码、原用户名：原样可登录，提示改进，不强制改密/重命名；新修改按新规则。
- 已完成安全迁移：校验状态后按凭据模式运行，旧 YAML 变动按正常内容加载，不再跑账号迁移。deployment 更新只响应有效源变化，local 不被遗留密码重置。
- 完成标记/库不一致、损坏、只读状态目录：faulted，明确完整恢复或修权限；不回退匿名或删除库重试。

### 9.4 可选维护 CLI

不提供强制内容计划命令，只保留必要维护工具，均支持可选 --state-dir；修改命令停机持锁。密码仅终端隐藏读取/密码文件，不在参数传明文。

- `flare security migration-check [--json]`：只读报告，更新前可用；正常启动也执行同一检查服务。报告不得自动输出私有 URL。
- `flare security init [--username NAME] [--password-file PATH]`：新实例/缺凭据待处理，不能覆盖 ready 账号。
- `flare security reset-password [--password-file PATH] [--take-local-control]`：本地恢复，撤销全部会话。
- `flare security set-credentials --mode local|deployment [--password-file PATH]`：显式切换来源，local 要设置/验证合规密码，deployment 要有效源；成功撤销旧会话。
- `flare security adopt-legacy-defaults`：只针对无其他证据的旧默认样例，确认可信旧行为，拒绝私有标记和矛盾配置。
- `flare security revoke-all`：停机撤销全部会话，完整目录恢复后首次启动前必须执行。

退出码：0 成功；2 配置/输入；3 锁冲突/状态不允许；4 存储/恢复错误。明确命令修改过哪些安全状态，但不输出密码。目录备份恢复使用运维复制，不要求新归档工具。

## 10. SPEC-09：升级失败、备份恢复与回滚

### 10.1 迁移失败的恢复

尚未提交时：保留源 YAML 与旧安全文件，修复错误配置/挂载/权限后重启，自动继续；不能清除 private 或停认证当通用修复。已提交但业务构建失败：保持新安全状态和错误证据，修内容配置再重启，不重新取旧密码。

断电留有迁移日志：程序识别同实例/输入摘要，幂等完成或回退未提交暂存，不能重复分配管理员和覆盖第一次快照。损坏无法安全确定则 faulted，提示恢复完整备份。

### 10.2 回旧版本的逐步流程

1. 停止新版，隔离公网入口；保留新版本全部 YAML、安全目录、日志摘要及升级后数据的独立备份。
2. 恢复升级前完整工作目录和原部署配置/Secret/挂载关系，使用升级前镜像摘要或二进制。不要仅改镜像、混用新旧隐藏状态。
3. 在隔离环境启动旧版，以无 Cookie 请求确认有效访问模式、编辑器、搜索、导出与原数据。
4. 特别检查任何 private=true 或新版私有分类：旧版不实施真实条目 ACL，恢复原公开站点会重新公开这些内容。对需继续保密的内容，必须在旧配置设置 DisableLogin=false + Visibility=PRIVATE 并确认有效，或先移除这些内容；不能因为是“原样恢复”就忽略已知泄漏。
5. 确认受限数据保护和管理边界后再开放公网。若选择回到历史可信匿名可写模式，记录该选择，不宣传拥有新权限能力。
6. 升级后新增/修改内容保存在独立备份，手工挑选合入；不要直接覆盖旧备份，也不要将 HTML/YAML 可解析等同于权限无损。

旧 Cookie 由升级前旧密钥决定，可能重新有效；安全事件回滚必须按旧版本支持的方式轮换 Cookie 密钥并重新登录。不能宣称恢复旧目录天然撤销旧会话。新版本登录凭据变化不会自动反写旧 FLARE_PASS，回滚使用旧配置凭据，注意遗留已泄漏密码。

### 10.3 恢复到新版本

停机复制完整一致性备份到目标目录，确认权限及 Secret 来源→执行 revoke-all（不启动监听）→按备份来源模式启动→检查账号、private 和匿名访问。撤销命令失败不得开放；备份会话只作为被撤销记录，不恢复登录。保留恢复前目录供撤回，禁止边运行边复制状态文件。只恢复某个 YAML 属内容恢复，不代表恢复账号或完整部署。

## 11. SPEC-10：界面、测试环境与实施门槛

访问与账号页只显示站点/管理有效模式、来源、当前管理员密码管理方式、退出当前/全部。私有选项嵌入原编辑器，分类限制来源可见，不出现成员/空间/角色词。部署管理转应用管理要有清楚影响确认；弱旧密码只提示，不阻止原使用。

基本登录/退出/改密/重新认证无脚本可用，中英文、键盘、屏幕阅读器、密码管理器、200% 字体、手机不横向溢出。独立登录页脚不执行旧 Footer。P1 匿名预览必须服务端以真实匿名主体生成，不发全量数据前端模拟。

Docker 与二进制均验收，HTTP/直 TLS/TLS 反代/非默认端口/IPv6/多个实例覆盖。Chromium、Firefox、Safari、iOS Safari、Android Chromium、Via 记录版本与结果，原生 amd64/arm64 和低配 ARM/NAS 记录设备；无真机证据不得宣称该问题已解决。多副本、完整子路径和网络盘共写不支持。

以 20,000 条资源（公开/私有各半，100 分类）测首页、搜索、导入及登录 p50/p95/RSS/吞吐，与同硬件同数据 0.6.7 比较；旧版不具备等价 ACL，比较注明差异。普通读取不能哈希密码或逐条查询安全库，哈希并发/队列有界，30 分钟登录压力无 OOM/无限增长。初始基准冻结版本化性能预算后才能完成性能签署；不在文档虚构已测阈值。

开发顺序：先 YAML 往返保留及安全状态故障协议、自动迁移与现有配置解析→统一授权和编辑/导入/跳转→会话/代理/界面→升级回滚与平台验收。每个 PR 提交路由覆盖清单、现有用户行为变化、对应 T 编号；不先建多人表或新内容库。

## 12. 验收用例与需求追踪

使用独立匿名 N、管理员 A1/A2 Cookie jar；公开分类 C、私有分类 D；C 中公开 P、private=true 的 S；D 中 private=false 的 Q；无分类私有应用 X。各条目唯一哨兵标题、描述、URL、图标；检查真实响应/日志/外发及磁盘，不只检查状态码。T01–T30 均为 P0，后续能力不纳入。所有 REQ 编号对应本次需求说明书。

### T01 — 新安装安全默认

映射：REQ-SETUP-01；SPEC-02/03。
空目录/仅发行样例启动无配置，N 得通用初始化提示/503，无导航管理数据，不生成公开可写站点；本地/Secret 初始化后默认登录+PRIVATE。显式 DEFAULT 与可信选择按规定生效，样例不误识别旧安装。

### T02 — 识别歧义与并发初始化

映射：REQ-SETUP-01、REQ-NFR-02；SPEC-02/03/08。
有非样例内容/历史安全文件/旧显式配置可识别；纯默认样例无证据时不自动公开，可本地 adopt。两个 init 仅一成功；标记提交前后杀进程，不覆盖账号、不变成新公开实例。

### T03 — 旧登录用户自动升级

映射：REQ-MIGRATE-01、REQ-MIGRATE-02；SPEC-08。
false+DEFAULT 与 false+PRIVATE，保留原模式/原用户名/原密码，不要求 migrate/重写 Compose；YAML 字节摘要不变，只建立安全状态。旧 Cookie 失效一次；后续正常重启不重复注销。

### T04 — 旧免登录用户兼容

映射：REQ-MODE-01、REQ-MODE-02、REQ-MIGRATE-02；SPEC-02/08。
可识别旧 true+DEFAULT 无 true 标记时，显式参数与旧默认来源都可自动运行，保留原内容读写，摘要分别标明来源/未知意图。不能升级后突然只读或要求建立管理员；账号/安全接口仍拒绝匿名。

### T05 — 免登录与私有标记冲突

映射：REQ-MODE-02、REQ-MIGRATE-03；SPEC-02/08。
旧分类/条目 true 与免登录组合进入 attention，不返回内容、不清标记；按提示开启登录并提供密码后自动完成，或停机逐项移除后继续可信运行。可信网页编辑/导入引入 true 整次拒绝。

### T06 — 矛盾配置及优先级

映射：REQ-MODE-01、REQ-MIGRATE-01、REQ-MIGRATE-02；SPEC-02/08。
CLI>.env>env>默认按原规则解析；true+PRIVATE、非法 Visibility/布尔、重复来源均报原始来源，不用纠正值假称成功。Compose 插值与容器环境区分，错误不回落公开。

### T07 — 原样 YAML 与可选分类字段

映射：REQ-DATA-03、REQ-ACL-01、REQ-ACL-02；SPEC-01。
旧三文件无新增字段可用，自动迁移不重写字节，无条目 ID/版本/成员字段。分类 true 和条目 true 生效；应用无分类仍支持 true。未知扩展字段经编辑/导入/导出往返保留。

### T08 — 父级限制和编辑器默认

映射：REQ-ACL-02、REQ-ACL-03、REQ-UI-01；SPEC-01/04。
N 可读 P 不可读 S/Q/X，Q=false 不绕过 D=true；管理员全可见。旧缺省继续原公开语义；编辑器新分类/无分类默认真、分类内继承并提示公开范围，不把保存旧条目当新建改默认。

### T09 — 外部文件、只读与重启

映射：REQ-DATA-03、REQ-DEPLOY-03、REQ-ACL-05；SPEC-01。
直接改三个 YAML，按既有缓存/重启流程加载，不需内容应用命令，不被内部状态覆盖。只读挂载可浏览，写入明确失败不写旁路副本；不宣称外部并发编辑立即生效。

### T10 — 所有读面和管理入口

映射：REQ-ACL-04、REQ-SURFACE-01；SPEC-04/06。
原始 HTML、搜索/联想、分页/计数、应用/分类、原始数据、导出/备份中 N 无 S/Q/X 哨兵；管理写入登录模式拒绝匿名。隐藏/不存在同样 404，未认证管理先 401，路由登记没有遗漏。

### T11 — 旧跳转、图标与外发

映射：REQ-SURFACE-02、REQ-SURFACE-04；SPEC-04/07。
保存旧编码跳转，资源变私有后旧链接不能跳转；重排后句柄不指错项。图标/预加载不泄漏，捕获网络证实私人信息不自动外发；若有服务端取图，完成 SSRF 负测或关闭。跳转 no-referrer，说明历史 URL 无法撤回。

### T12 — 缓存、重启与权限快照

映射：REQ-SURFACE-03、REQ-ACL-05；SPEC-01/04。
公开读后转私有，旧 ETag/If-None-Match 无未授权 304或受限正文；管理员/N 经代理不串内容。外部文件改权限后重启，导航/跳转缓存全部重建。内存发布失败停止业务不沿用旧权限。

### T13 — 并发编辑与文件写失败

映射：REQ-ACL-05、REQ-NFR-02、REQ-SETUP-02；SPEC-01/05。
A1/A2 同文件摘要，A1 保存后 A2 409；手工改文件也使旧表单/导入失效。备份失败、磁盘满、暂存/rename 失败保持旧文件。权限放宽需近期认证和确认，撤销会话的并发写提交前被拒绝，不伪造跨文件事务。

### T14 — 旧凭据来源保持

映射：REQ-ACCOUNT-03、REQ-MIGRATE-04；SPEC-03/08。
显式旧源自动 deployment；Compose 更新后重建按新源登录，旧密码/Cookie 失效；相同源重启不注销。原短密码与原用户名可登录，仅提示。无历史有效源不生成假“原密码”，待本地处理并保持原访问模式。

### T15 — 网页改密和来源切换

映射：REQ-ACCOUNT-04、REQ-ACCOUNT-03；SPEC-03/05。
deployment 网页直接改密拒绝；明确验证并转 local 后能改密，旧 Compose 密码不再覆盖。local→deployment 仅显式本地切换；环境模式冲突报错。改密与全部撤销故障注入原子，新 Cookie 写出失败用新密码重新登录。

### T16 — 密码/Secret 格式和旧密码豁免

映射：REQ-ACCOUNT-01、REQ-ACCOUNT-02、REQ-ACCOUNT-03；SPEC-03。
新密码长短/Unicode/空格/弱口令校验，旧非空源按原值接受；不 trim/归一化。FILE 单次 LF/CRLF、重复换行、空/缺失/只读/不可读、明文冲突有确定行为；local 不依赖失效遗留文件，deployment 缺源拒绝。日志/错误无密码/哈希。

### T17 — 会话过期与重新认证

映射：REQ-SESSION-01、REQ-SESSION-02；SPEC-05。
闲置 30 分钟、绝对 12 小时服务端到期，天气等不续期；超过 10 分钟敏感操作 REAUTH_REQUIRED，重新验证轮换不延绝对期。无长期设备选项，Cookie 参数正确，普通重启保持未过期状态。

### T18 — 当前/全部退出与时钟

映射：REQ-SESSION-03；SPEC-05。
复制 A1/A2 Cookie，退出当前只影响 A1，全部退出均失效，重启仍失效。前跳到期再回拨不复活，超过 60 秒回拨撤销、写失败 faulted；无脚本也不能继续写。

### T19 — 状态损坏、持久化和单写者

映射：REQ-DEPLOY-04、REQ-NFR-02；SPEC-03/08。
完成后丢库/丢标记/损坏/只读不当新实例，503 不回匿名。全目录挂载自动创建安全目录，逐文件挂载按文档补目录并重建验证；不暗用临时目录，第二实例锁冲突拒绝。记录无法自动检测挂载的限制。

### T20 — 来源、CSRF 和代理

映射：REQ-DEPLOY-01、REQ-DEPLOY-02；SPEC-05/07。
HTTP/TLS/反代/IPv6/端口/Host/Cookie 组合通过；伪造 XFF/Host/Proto 不改变信任，明确 HTTPS 不降级。全部浏览器写入口包括登录/退出/可信编辑有 CSRF；跨站 Origin/null 不放行，缺 Origin/Referer/Fetch Metadata 按规定回退，无脚本可提交。

### T21 — 导入兼容与权限

映射：REQ-DATA-01、REQ-NFR-04；SPEC-06。
原格式/重复规则/8 MiB/20,000/32 层/15 分钟保持，默认私有与显式公开预览准确，重复更新不清 true/分类限制。可信导入仅纯公开，true 拒绝。未知字段保留、非法 private/重复键/悬空分类拒绝，恶意链接/文本不执行，预览篡改/陈旧 409，失败不改文件。

### T22 — 导出和既有备份下载

映射：REQ-DATA-01、REQ-DATA-02；SPEC-06/09。
原备份入口仍在但认证/可信规则完整，登录模式匿名不能下载。YAML 保留分类/条目 true，无账号秘密；HTML 提示丢权限，私人导出确认及近期验证；流开始前重校验，不宣称阻止复制。

### T23 — 自动快照与迁移中断

映射：REQ-MIGRATE-01、REQ-NFR-02；SPEC-08/09。
快照/日志/标记各阶段杀进程，原 YAML/旧密钥未改，重试不覆盖第一次有效备份、不重复建账号。快照失败不迁移，输入变化中止，日志不含明文源。区分内部快照和运维完整备份。

### T24 — 回旧版本演练及隐私降级

映射：REQ-MIGRATE-05；SPEC-09。
执行停机/保存新版数据/恢复完整旧目录和配置/原镜像/隔离验证/再开放；不是只换镜像。含私有分类/条目的公开旧版必须全站登录或移除受限内容；验证旧 Cookie 可能复活并记录密钥轮换，升级后新内容另存，不能无审查合并。

### T25 — 新版完整恢复

映射：REQ-DATA-02；SPEC-09。
停机一致性备份恢复后，revoke-all 再启动，旧 Cookie 全失效，账号与内容不丢，来源模式/Secret 正确。撤销失败不开服务；只恢复 YAML 不误称恢复完整实例，保留恢复前回退副本。

### T26 — 本地密码恢复

映射：REQ-ACCOUNT-04；SPEC-03/08。
有目录权限且持锁可 local 设密，全旧会话撤销；deployment 默认提示改源，显式 take-local-control 才切模式。锁冲突/无权限失败，无明文参数/网页恢复令牌/关闭认证步骤；原站点模式保留。

### T27 — HTTP、返回地址和真实错误

映射：REQ-LOGIN-01、REQ-LOGIN-02、REQ-LOGIN-03；SPEC-06。
400/401/403/404/409/413/429/503 与 code/request_id/日志一致，未知用户名同错密码。非法 return_to 回首页，不重放 POST，GET 不写；Cookie 拒绝不循环，未保存草稿无虚假保留提示，诊断不泄漏配置。

### T28 — 登录页、旧 Footer 和无脚本

映射：REQ-UI-02、REQ-UI-03、REQ-DEPLOY-03；SPEC-06/10。
登录/错误页无旧 HTML 页脚/私人标题/详细版本；独立 LoginFooter 安全链接可用，公开导航旧 Footer 保持，私有导航登录后保持。无脚本登录/退出/改密/重新验证，键盘、屏幕阅读器、手机、字体/自动填充正常；基本诊断管理员可见。

### T29 — 限流与低配资源

映射：REQ-LOGIN-04、REQ-NFR-01；SPEC-03/07/10。
未知/存在账号限流一致，伪造头不换桶，NAT 冷却后可恢复，不永久锁定；桶/哈希并发/队列按上限拒绝，Retry-After 正确。普通请求无密码哈希，30 分钟压力无无限资源增长，冻结性能预算并提供同硬件对比。

### T30 — 用户升级指南和平台证据

映射：REQ-MIGRATE-04、REQ-MIGRATE-05、REQ-NFR-03；SPEC-08/09/10。
分别用目录挂载、逐文件挂载、只读内容、二进制部署复现完整指南；正常用户不需迁移/内容应用命令，异常路径可按提示恢复。保存浏览器/架构/真机版本证据，Docker 环境变化用重建，明确不支持项与未测项；不把文档通过当功能通过。
